# Demo 4: GPU training with shared Blob Storage

Use five Kubeflow tasks to prepare data in East, train on West's GPU, and evaluate the saved model back in East. Azure Blob Storage holds the files shared between the clusters.

| Task | Runs in | Saves to Blob Storage |
| --- | --- | --- |
| Prepare data | East, CPU | Training and validation datasets |
| Validate data | East, CPU | Checked dataset manifest |
| Train remotely | East submits; West trains on GPU | Model, checkpoint, and training manifest |
| Evaluate model | East, CPU | Validation metrics |
| Publish results | East, CPU | Result manifest linking the artifacts |

The sample generates a small synthetic dataset and trains a linear regression model. Publication runs only when the model passes the evaluation threshold.

## 1. Set up once

Follow [Demo 4 setup](SETUP.md), then return here in the same terminal. It prepares Blob Storage, identities, images, and Fleet access. No earlier demo needs to be run.

## 2. Run the pipeline

In a **second terminal**, open the repository root and keep this running. If you chose another `STATE` directory, use its `east` kubeconfig:

```bash
kubectl --kubeconfig .state/east -n istio-system \
  port-forward svc/istio-ingressgateway 8088:80 --address 127.0.0.1
```

In the **first terminal**, refresh access and submit:

```bash
bash "$EXAMPLE/scripts/refresh-access.sh"
.venv/bin/python "$EXAMPLE/scripts/run-pipeline.py" \
  --pipeline "$STATE/pipeline.yaml" --account "$STORAGE_ACCOUNT" \
  --target "$WEST" --namespace "$PROFILE" --output "$STATE/run.json"
```

Enter your Kubeflow password. The helper prints a run link and waits for completion. It uses the demo's Dex login and sets the required `blob-pipeline` service account.

## 3. Check the five tasks

Open the printed run link and sign in. In the run graph, click a task, then **Logs**. All five tasks should succeed.

- **Train remotely:** look for the West member name, GPU name, and successful training.
- **Evaluate model:** check that mean squared error is below the default threshold of `0.02`.
- **Publish results:** check the saved result manifest.

Fleet uses **PickFixed** with `target_member` (West by default). The pipeline task stays in East; Fleet places a separate PyTorchJob on West. It starts a new training execution, not a live migration.

## 4. Inspect the shared files

In Azure Portal, open your storage account → **Data storage → Containers → fleet-demo4 → runs**. Open the run's folder, including its datasets, model/checkpoint, evaluation metrics, and `published/result.json`.

Each run's folder is the first 24 characters of the SHA-256 hash of its run ID. [Portal access setup](SETUP.md#5-optional-browse-files-in-azure-portal) grants your user permission to read these files.

West reads the data East saved; East then reads the model West saved. Blob access uses Workload Identity. Kubernetes API access uses separate, short-lived credentials.
